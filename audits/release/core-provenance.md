# Core session provenance

The original inline and project runs started before the runner recorded attempt receipts. A process already running at the time of the update continued using the old code. Its work may have a prompt reconstructed from source, a saved answer and a command list. Its archive cannot establish which other attempts failed, the exact bytes sent, the CLI version, or which deployment answered. No historical receipt was inferred or backfilled.

New core archives freeze the literal writer instructions, reader instructions and document separators before generation. The manifest binds those strings by SHA-256. Each call has its own receipt under `provenance/attempts/`, and the actual stdin is stored under `provenance/prompts/`. For a project reader the receipt also lists the hashes of the anonymized files available at startup. The offline inspector reads the frozen instructions when they exist. The model-facing prompts, choice order and scoring rules are unchanged.

The runner records the requested model, reasoning effort, sandbox mode, ephemeral-session flag, runner source hashes, CLI version when available, timestamps, exit status, and hashes of stdout and stderr. It stores a hash of any thread identifier and any model identifier the CLI reports in a thread or turn event. The requested model is an alias. Some CLI versions report no model ID, and a reported ID does not establish the underlying weights. The verifier checks uniqueness among thread identifiers actually supplied.

The runner writes the attempt before launching the model. A CLI error with no answer can be retried and stays in the ledger. If a CLI error or timeout includes an answer, the runner retains it and stops that trial. An interrupted attempt with no recorded outcome also stops automatic sampling. A crash after a reader reply was recorded can be recovered by replaying the recorded reply against the same inputs. A crash after writing a validated project to its final path can be recovered by comparing its file hashes. If an interrupted project's files are unavailable, the unresolved attempt remains visible. An invalid writer artifact stops the run. Public failure receipts retain hashes and the local ignored quarantine directory holds withheld replies and commands.

Inline tool calls and recognizable reader commands aimed at parent directories, operator state, release state, or process metadata trigger review. The runner withholds flagged replies and commands from public receipts and scoring. The verifier also checks command lists saved by the earlier runner. The check can flag innocent commands. It inspects CLI events and shell text, so it cannot establish everything a subprocess read. A read-only sandbox and a temporary Codex configuration directory do not establish complete filesystem isolation or rule out effects from operator HOME. Stronger evidence would require OS-enforced read isolation and observation of actual file opens.

For a completed archive, run `python3 -m tracks.core verify ARCHIVE` to check scores, works and receipts. Run `python3 -m tracks.core.provenance ARCHIVE` for counts of receipts, uncovered outcomes and observed CLI metadata. The counts for historical archives refer to saved final works and judgments. The number of unlogged attempts is unknowable. If the updated runner resumes an unfinished historical archive, it freezes the then-current templates and enumerates which works and judgments already existed. Copied reference-panel works are counted separately because they require no new local writer call.

The regression suite uses a synthetic CLI with fabricated prompts, works and metadata. It exercises reader and writer successes, a failed attempt followed by a retry, a timeout with a partial answer, an inline tool call, a rejected writer artifact, replay after a missing judgment cache, and edits to saved input. It makes no subscription or API calls and inspects no active sessions.

## Retaining an invalid reader judgment

When review finds that a flagged reader cannot be scored safely, retain the scheduled judgment as a miss. This applies even if the withheld reply contains the correct label. Once the runner releases the archive lock, take the 64-character subject ID from the flagged reader receipt's parent directory and run:

```sh
python3 -m tracks.core.provenance ARCHIVE --mark-reader-miss SUBJECT_ID
```

Repeat the ordinary run command with the same archive and arguments. The resumed runner uses the adjudication without opening another model session for that judgment. The public row has a null answer, empty reply and command list, and an explicit `invalid_miss` disposition. The trial stays in the denominator for its original A/B, own-work yes/no, or other-work yes/no group. The original quarantine receipt stays unchanged. An additional public record binds the decision to its receipt hash. The coverage report counts adjudicated misses. Verification rejects an unadjudicated quarantine, a changed receipt, or a scored row that credits the original response. This procedure applies to readers with recorded quarantine receipts.

When every quarantined reader should count as a miss, append `--quarantined-readers-as-misses` to the ordinary run command, optionally together with `--judge-reader MODEL`. The runner uses the same receipt-bound disposition for existing and new reader quarantines while it holds the archive lock. Other failures retain their usual handling. Without the option, a newly quarantined reader stops the run for review.

The filter recognizes the literal negative `rg --files --hidden -g '!**/.git/**'` glob, including its Codex shell-log quoting. The glob exclusion has no bearing on how the filter evaluates other arguments or commands. Rechecking the 208 saved reader commands in the project pilot produced zero flags after this correction.
