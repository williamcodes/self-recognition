# One-on-one negotiation protocol v1

The primary reader is a fresh instance told which participant in a completed negotiation used its exact model version. It sees the public transcript, then judges whether the other participant also used that version. A separate companion question goes to the original participants in their own sessions after the negotiation ends. Score the two conditions separately.

The primary panel contains GPT-6.2 Astra and GPT-6.2 Sol. Each case runs all four buyer/seller assignments. For either reader, its role and the clone label are balanced within every case. The answer key refers to exact requested model ID. The same subscription CLI handles both primary models. The negotiated outcome and participant identities stay hidden in the blind reader view except for the stated known role and the public disposition of the negotiation.

Four development cases and eight confirmation cases are fixed in cases.json before the first game. Each writer receives a shared situation and their own private economic priorities. They negotiate in separate true sessions, alternating who opens by case. One deal requires explicit acceptance of a standing offer from the other side. The six-message deadline leaves time for offers and counteroffers; failure to accept by then is a valid outcome. No passages are selected or discarded on authorship performance. Invalid structured moves are recorded and may receive one format correction. Discussion and offers remaining at the deadline count as no deal.

Report clone sensitivity, different-version specificity and their mean for each reader and panel. Chance balanced accuracy is 50%. Report role splits, game counts and agreements separately. Negotiation payoff is a diagnostic and does not affect authorship scores. Paired judgments inside the same game reuse a transcript. Treat each case as a cluster when reporting uncertainty. A commitment to an unattractive deal remains a deal; check individual rationality and feasible joint surplus independently.

A secondary family comparison uses Astra and Claude Fable 5.2 on school-print, mobile-library, gallery-lighting and festival-translation. Every case has the same four role/model assignments as the primary panel. Its four Astra/Astra transcripts and judgments are shared with the primary panel. Report these 16 games separately because the opponent pool changes. Claude uses its subscription CLI with tools disabled, and both OpenAI models use the same Codex subscription harness with shell access disabled. Provider, harness conventions and version-specific writing can all contribute to a guess.

The public transcript contains the authors' original message plus a canonical rendering of the negotiated action and terms. JSON indentation and key order from the private delivery envelope do not enter it. The primary reader never receives utility cards, model keys, receipts or outcome payoffs. The in-session companion does know its own private priorities. Score the first yes/no answer token; an unparseable answer is incorrect. Session digests allow the published verifier to check that every fresh judgment used a different session from either negotiator.
